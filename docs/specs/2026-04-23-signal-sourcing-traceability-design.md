# Signal Sourcing & Traceability — Design Spec

**Axis A of the 4-axis backend signal-quality optimization effort.**
Siblings (out of scope for this spec): B — embedding/clustering quality; C — event↔market matching; D — heuristic scoring + outcome feedback loop.

---

## Goal

Every signal that reaches the user must (1) cite its underlying news articles with clickable links to the original source, (2) carry a 3–5-sentence LLM-generated explanation of why those news items move that specific Polymarket market, and (3) be backed by a normalized, auditable source-reputation model. No signal can exist without `reasoning` and at least one source article — hard invariant enforced by the signal builder.

---

## Current State (snapshot 2026-04-23)

**Works**:
- `sources_registry` table with 45 seeded sources (tier 1/2/3, weight 0.3–1.0)
- RSS scraper (`app/ingestion/rss_scraper.py`) fetching from Reuters, BBC, Guardian, NYT Politics, AP, Politico, Al Jazeera, The Hill, Washington Post, etc. — thousands of articles ingested
- X/Twitter via RSSHub (public `rsshub.app`) for whitelisted accounts
- WorldNewsAPI as secondary aggregator
- Schema for traceability exists: `signals.event_id` → `events.id` → `event_news_links.clean_id` → `news_clean.news_id` → `news.id`
- LLM called once per signal to generate `catalyst` (short headline) + `llm_impact_score` + `llm_confidence`

**Missing**:
- `news.source_id` FK to `sources_registry` (link today is via `source_name` string match — fragile)
- No `reasoning` (the "why this matters" LLM explanation) on signals
- No per-article `key_excerpt` / `relevance_score` on `event_news_links`
- No GDELT ingestion
- Public RSSHub is unreliable (rate-limited, frequent downtime)
- API `GET /api/signals/{id}` does not return sources, reasoning, or timeline
- Frontend `SignalDetail` page never shows source articles
- No admin/debug endpoint for source reputation audit

---

## Architecture

Additive extension of the existing pipeline. No rewrite. Five changes, layered:

1. **DB normalization** — migrations to add `news.source_id` FK, `signals.reasoning`, `event_news_links.key_excerpt` + `relevance_score`, plus a GDELT staging table.
2. **Ingestion additions** — new `fetch_gdelt` Celery task; self-hosted RSSHub container to replace unreliable `rsshub.app`.
3. **LLM upgrade** — extend the existing per-signal LLM call with structured output that includes `reasoning` + `article_excerpts[]`. No increase in LLM call count.
4. **API surface** — enrich `GET /api/signals/{id}` response; add `GET /api/signals/{id}/sources` and `GET /api/sources`.
5. **Frontend UI** — three new components in `SignalDetail`: `<WhyThisMatters>`, `<SourcesList>`, `<SignalTimeline>`.

**Invariants enforced post-Axis-A**:
- Every signal row has `reasoning` (not null, ≥ 100 chars).
- Every signal references at least one `event_news_links` row where `key_excerpt` is non-null.
- Every `event_news_links.key_excerpt` is a literal substring of the source article's `clean_text`.

**Non-goals**:
- Dynamic source-reputation (outcome-driven weights) — that is Axis D.
- Per-event cluster-parameter tuning — Axis B.
- Market-matching algorithm changes — Axis C.

## Data Model Changes

### Migration 014 — Normalize `news` → `sources_registry`

```sql
ALTER TABLE news ADD COLUMN source_id INTEGER REFERENCES sources_registry(id);
CREATE INDEX ix_news_source_id ON news(source_id);

-- Backfill
UPDATE news
SET source_id = sr.id
FROM sources_registry sr
WHERE news.source_name = sr.source_name;
```

`source_name`, `source_tier`, `source_weight` remain on `news` as a historical snapshot (useful for audit if a source later changes tier). `source_id` is nullable to keep the migration non-breaking; the API code treats `source_id IS NULL` as legacy-ingestion rows.

### Migration 015 — Add `reasoning` and traceability metadata to `signals`

```sql
ALTER TABLE signals ADD COLUMN reasoning TEXT;
ALTER TABLE signals ADD COLUMN llm_model_version VARCHAR(50);
ALTER TABLE signals ADD COLUMN source_tier_mix JSONB;
```

- `reasoning`: 200–400 chars, 3–5 sentences, generated by the LLM at signal creation.
- `llm_model_version`: e.g. `"gpt-4o-mini-2024-07-18"` — lets us re-run older signals if we swap models.
- `source_tier_mix`: e.g. `{"tier_1": 3, "tier_2": 1}` — derived counts, used for display badge and quick filtering.

### Migration 016 — Article-level excerpts on `event_news_links`

```sql
ALTER TABLE event_news_links ADD COLUMN key_excerpt TEXT;
ALTER TABLE event_news_links ADD COLUMN relevance_score REAL;
```

Excerpt lives on the link (not on `news_clean`) because the same article may contribute to multiple events with different excerpts.

### Migration 017 — GDELT staging

```sql
CREATE TABLE gdelt_events_raw (
    id BIGSERIAL PRIMARY KEY,
    gdelt_event_id VARCHAR(64) UNIQUE NOT NULL,
    source_url TEXT,
    published_at TIMESTAMPTZ,
    actor1 TEXT,
    actor2 TEXT,
    event_code VARCHAR(10),
    tone REAL,
    raw_data JSONB,
    ingested_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX ix_gdelt_events_raw_published_at ON gdelt_events_raw(published_at DESC);
```

GDELT's schema is very different from RSS; we stage the raw payload, then normalize promising rows into `news` via the `fetch_gdelt` task.

### Migration 018 — Point X/Twitter sources to self-hosted RSSHub

```sql
UPDATE sources_registry
SET url = REPLACE(url, 'https://rsshub.app', 'http://rsshub:1200')
WHERE source_type = 'x_rss';
```

### SQLAlchemy model changes

In `app/db/models.py`:
- `News`: add `source_id: Mapped[Optional[int]]` with `ForeignKey("sources_registry.id")` + `source: Mapped[Optional["SourceRegistry"]] = relationship()`.
- `Signal`: add `reasoning`, `llm_model_version`, `source_tier_mix`.
- `EventNewsLink`: add `key_excerpt`, `relevance_score`.
- New `GdeltEventRaw` model.

## Ingestion

### GDELT (new)

**Module**: `app/ingestion/gdelt_client.py`

```python
class GdeltClient:
    BASE_URL = "https://api.gdeltproject.org/api/v2/doc/doc"

    async def fetch_recent(
        self, query: str, timespan: str = "15min", max_records: int = 250
    ) -> list[ArticleDict]:
        """Return articles matching `query`, seen in the last `timespan`."""
```

Maps each GDELT row to `ArticleDict` with keys: `url`, `title`, `text` (empty — GDELT doesn't return full text; we leave it to downstream extractors), `source_name` (derived from URL domain via `tldextract`), `publish_date`, `ingestion_lag_seconds`.

**Source creation on unknown domains**: if `source_name` does not match any row in `sources_registry`, auto-create a row with `tier=3, weight=0.4, active=true, source_type='gdelt_auto'`. This gives us visibility on new sources that GDELT surfaces.

**Celery task**: `app/workers/tasks_ingestion.py::fetch_gdelt`

- Scheduled every 5 minutes via beat.
- Reads queries from `sources_registry` rows where `source_type='gdelt_query'` (seeded).
- For each query: fetches articles, filters to `sourcelang:eng`, dedupes by URL, inserts into `news` with `source_id` resolved.

**Seed queries** (stored in `sources_registry` rows): politics, ceasefire, FOMC/rates, crypto regulation. Editable by ops.

### RSSHub self-hosted

Add to `docker-compose.yml`:

```yaml
rsshub:
  image: diygod/rsshub:latest
  restart: unless-stopped
  environment:
    CACHE_TYPE: redis
    REDIS_URL: redis://redis:6379/5
    NODE_ENV: production
  depends_on:
    redis:
      condition: service_healthy
  ports:
    - "1200:1200"
```

Migration 018 rewrites URLs in `sources_registry`. The existing `rss_scraper.py` doesn't need changes — it already reads URLs from the registry.

### Existing ingesters updated

`rss_scraper.py`, `worldnews_client.py`, and new `gdelt_client.py` all write `source_id` at insertion time (resolved from registry), so once the backfill is done, `source_name` matching is only a fallback for legacy rows.

## LLM Reasoning + Excerpts

**Extension of the existing per-signal LLM call** (`app/scoring/llm_analyzer.py`). No new call — the existing call gains richer output.

### Prompt inputs

- Event: `event_title`, `event_summary`
- Top-N articles (N=5), ordered by cosine similarity event↔article, with `news_clean.id`, `title`, `source_name`, `clean_text[:800]`, `publish_date`
- Market: `market.question`, `market.price`, `market.direction_hint`

### Structured output (JSON schema / function calling)

```json
{
  "impact_score": 0.0,
  "confidence": 0.0,
  "catalyst": "string <= 120 chars",
  "reasoning": "string 200-400 chars, 3-5 sentences — explains why these news move THIS market",
  "direction_recommendation": "YES" | "NO" | "UNCLEAR",
  "article_excerpts": [
    {"news_clean_id": 42, "excerpt": "verbatim substring <= 200 chars", "relevance": 0.0}
  ]
}
```

### Quality rules enforced in the prompt

- `reasoning` MUST cite at least one article by its `source_name`.
- `excerpt` MUST be a literal substring of the corresponding `clean_text` (paraphrases forbidden).
- If no article is genuinely relevant → `direction_recommendation=UNCLEAR` + short `reasoning` explaining why → the signal is rejected (not persisted).

### Validation (Python-side, post-LLM)

- `reasoning` ≥ 100 chars and mentions ≥ 1 source name from the input set → else reject signal.
- For each `excerpt`: `excerpt in clean_text` (string containment). If not, nullify that excerpt; keep the others.
- If 0 valid excerpts remain → reject signal.

### Model & cost

- `gpt-4o-mini` (`gpt-4o-mini-2024-07-18`), temperature 0.3, structured output via `response_format={"type": "json_schema"}`.
- Estimated cost: ~$0.002/signal × ~200 signals/day ≈ **$12/month**.

### Fallback and quota handling

- Transient errors (timeouts, 5xx): retry 3× with exponential backoff (existing behavior).
- Hard failure after retries → signal rejected (no partial rows — invariant preservation).
- 429 quota-exceeded → circuit breaker: log `QUOTA_EXCEEDED`, mark the pending signal in `signals_pending_reasoning` staging table (new), replay via a `backfill_reasoning` task when quota returns. (Staging table added as part of Migration 015 — `CREATE TABLE signals_pending_reasoning (id SERIAL PRIMARY KEY, event_id INT, market_id TEXT, inputs JSONB, created_at TIMESTAMPTZ DEFAULT NOW())`.)

### Persistence

On success:
- `signals.reasoning` ← `reasoning`
- `signals.llm_model_version` ← model ID string
- `signals.source_tier_mix` ← computed counts from input articles
- For each valid excerpt: `UPDATE event_news_links SET key_excerpt = ..., relevance_score = ... WHERE event_id = ? AND clean_id = news_clean_id`

## API Surface

### `GET /api/signals/{id}` (modified — additive)

Response gains:

```json
{
  "id": "239",
  "question": "...",
  "direction": "YES",
  "score": 71,
  "catalyst": "Trump announced...",
  "reasoning": "3-5 sentences explaining why these news move this market...",
  "llm_model_version": "gpt-4o-mini-2024-07-18",
  "source_tier_mix": {"tier_1": 3, "tier_2": 1},
  "sources": [
    {
      "news_id": 12345,
      "title": "Trump announces...",
      "url": "https://reuters.com/...",
      "source_name": "Reuters Top News",
      "source_tier": 1,
      "source_weight": 1.0,
      "publish_date": "2026-04-23T14:03:00Z",
      "excerpt": "literal substring extracted by LLM...",
      "relevance_score": 0.92,
      "role": "primary"
    }
  ],
  "timeline": [
    {"at": "2026-04-23T14:03:00Z", "source": "Reuters", "type": "news", "headline": "..."},
    {"at": "2026-04-23T14:47:00Z", "source": "Bloomberg", "type": "news", "headline": "..."}
  ]
}
```

`sources` is sorted by `relevance_score DESC`. `timeline` includes news events only for Axis A; market-move entries are deferred to Axis C once market-price timeseries is wired up.

### `GET /api/signals/{id}/sources` (new)

Lightweight endpoint returning only the `sources` array — for lazy-loading in UI if needed.

### `GET /api/sources` (new, admin/debug)

Lists all active sources with operational stats:

```json
[
  {
    "source_name": "Reuters Top News",
    "tier": 1,
    "weight": 1.0,
    "active": true,
    "source_type": "rss",
    "articles_24h": 47,
    "signals_contributed_7d": 12
  }
]
```

### `GET /api/signals` (list — unchanged in response shape)

The list endpoint does NOT include `reasoning`/`sources` for performance. Those fields are only served in the detail endpoint.

### Contract tests

In `tests/integration/test_signal_detail_api.py`:

- A signal with 3 sources returns `sources[]` sorted by `relevance_score DESC`.
- `source_tier_mix` counts match the actual tiers in `sources[]`.
- A signal without `reasoning` in DB (legacy pre-Axis-A) returns `reasoning: null` and a warning flag — the API does not 500 on legacy rows.

## Observability & Operational Notes

- `logger.info` in `signal_builder.py` on every reject-due-to-invariant (missing reasoning, no valid excerpts). Include event_id + market_id + reject reason so ops can debug.
- Metric counters (log-based, no new Prometheus for Axis A): `signals.created`, `signals.rejected_no_reasoning`, `signals.rejected_no_excerpts`, `llm.quota_exceeded`.
- `signals_pending_reasoning` table size is a direct health signal — if > 100 rows, OpenAI quota is out.
- GDELT new-source auto-creation (tier=3, weight=0.4) emits a log line: `sources_registry: auto-created source '{domain}' from GDELT`. Ops review weekly to re-tier manually.

## Rollout

1. Migrations 014–018 applied in order (all backward-compatible).
2. Deploy updated workers (`fetch_gdelt` runs from next beat tick; RSS scrapers use `source_id`).
3. Deploy updated signal builder (new signals get `reasoning` + `source_tier_mix`).
4. Deploy updated API (existing responses gain new fields, old clients unaffected).
5. Deploy frontend (new components render where data is present, hide where it's not).
6. Backfill legacy signals: one-off script `scripts/backfill_reasoning.py` runs the LLM over the last N days of signals with `reasoning IS NULL`. Opt-in, not part of the critical path.

**Rollback**: each migration is reversible; frontend components self-hide when data is null. Safe to roll back any single layer without cascade.

## Open Questions (none blocking)

- GDELT seed queries: starting list is domain-agnostic. Axes B/C may later swap this out with category-targeted queries once we understand which prediction-market categories yield the best signal ROI.
