## Conventions for every wave

### Naming the keys

- Match the JSX hierarchy: `signals.filters.scoreLow` (not `signals.scoreLowFilter`).
- Verbs over nouns when both work: `signals.actions.refresh` (button label).
- Pluralize via i18next plurals: `signals.count` + `signals.count_plural`.

### Interpolation

Use `{{var}}` syntax: `signals.lastUpdated: "Mis à jour il y a {{ago}}"`.

### Aria attributes

Migrate them too: `aria-label={t("signals.filters.scoreLowAria")}`.

### What to NOT migrate

- Comments / docstrings / JSDoc
- Type names, enum values
- Code strings (URLs, log messages, throw/Error in dev paths)
- Test files
- The voice-guide markdown
- Showcase pages (`SignalCardVariants.tsx`, `SignalVariants.tsx`) — design-comparison, not prod CTAs

### Tests

Each migrated component that has a test file must mock `react-i18next` like the OrderForm test pattern:

```ts
vi.mock("react-i18next", () => ({
  useTranslation: () => ({
    t: (key: string, vars?: Record<string, unknown>) => {
      const dict: Record<string, string> = { /* … FR strings the test asserts … */ }
      return dict[key] ?? key
    },
  }),
}))
```

This keeps tests deterministic without booting the i18next provider.
