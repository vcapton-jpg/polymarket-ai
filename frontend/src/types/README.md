# Frontend types

Two flavours coexist:

## `signal.ts` — hand-curated

The user-facing domain types (`Signal`, `Position`, `PerformanceStats`,
`UserProfile`, etc.) the components actually consume. These are kept
**hand-written** because:

- They drift from the API shape on purpose (UI-only fields like
  `correctPrediction`, `category`, computed display values).
- Several pages (Signals, Portfolio) accept BOTH a real API payload
  and a static mock dataset (`MOCK_SIGNALS`, `MOCK_POSITIONS`) — the
  hand-typed shape is the union both must satisfy.
- Type names align with French/EN copy in components, not with the
  Python pydantic class names.

## `api.generated.ts` — codegen, do not edit

Generated by `npm run gen:api` from the live FastAPI OpenAPI spec at
`http://localhost:8001/openapi.json`. Regenerate after any backend
schema change (new endpoint, new field, removed field).

Audit follow-up 2026-05-05 (M6) — pre-PR, every TS type was
hand-written, so a backend rename / new field silently passed type
checking on the frontend. Now `api.generated.ts` is the source of
truth for "what the API actually emits"; pages that want strict
backend conformance can import the relevant `components["schemas"][…]`
type and let `tsc` flag drift on every PR.

### Migration policy (incremental)

We do NOT rewrite all hand-typed shapes at once. The generated file
is a tool: when you touch a page that hits `/api/<x>`, replace the
hand-typed call signature with `paths["/api/<x>"]["get"]["responses"][200]`
or `components["schemas"]["XOut"]` — whichever is more readable. The
two flavours coexist indefinitely.

### When to regenerate

- Backend ships a new endpoint or schema → run `npm run gen:api`
  before the frontend PR that consumes it.
- CI: not yet wired. The current contract is "regenerate when needed,
  commit the generated file alongside the consumer change."
